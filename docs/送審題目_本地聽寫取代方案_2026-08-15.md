# 設計諮詢：用官方逐字稿當標準答案，校正本地 Whisper 聽寫的專有名詞弱點

請你以資深工程師角色**挑戰**這個設計，不要附和。我要的是可執行方案 + 我沒想到的陷阱。
最後請給「建議的執行步驟」，因為這份會被轉成任務書交給另一個 AI 直接執行。

## 專案背景（真實情況，非假設）

`stock-signal`：把 podcast「股癌」逐字稿餵給 Gemini 萃取個股訊號（看多/看空），寫進 PostgreSQL，算勝率，出報告網頁。

- 逐字稿**唯一來源**是第三方網站 `whatmkreallysaid.com`（687 集）。對方停更/關站就斷炊，這是要解決的根本問題。
- 已有本地聽寫管線（yt-dlp 下載 YouTube + faster-whisper `large-v3-turbo`, CUDA）當第二來源，但**準確度不足以取代**。
- 使用者的最終目標（原話）：「下次分析我們之前聽寫的，跟官方逐字稿比，把專有名詞的弱點修正，之後取代他。」
  → 官方稿是**現成的標準答案**，用來校正我方聽寫；練到夠準就甩掉來源站。

## 已實測的事實（2026-08-15，樣本 = EP687 一集）

| 項目 | 數字 |
|---|---|
| 聽寫耗時 | 261 秒/集（GPU） |
| 內容完整度 | 去標點後 我方 19,837 字 vs 官方 19,607 字（**我方還多 1.2%**，開頭結尾都對得上，無漏段） |
| 段落層級相似度 | 88.34%（用 `difflib.SequenceMatcher`），但**只回報 1 個 diff block，等於沒有鑑別度** |

**專有名詞錯誤（訊號最密集的一段，主持人一次點名 5 檔）**：

| 正確 | 我方聽成 | 類型 |
|---|---|---|
| 台積電 | **臺**積電 | 異體字 台/臺 |
| 台達電 | **臺**達電 | 異體字 |
| 奇鋐 | 奇虹 | 同音誤聽 |
| 貿聯-KY | 茂林KY | 誤聽 + 格式 |
| 載板 | 載版 | 同音錯字 |
| （非個股）股癌→古來、謝孟恭→聖夢公 | | 人名/節目名 |

該段 5 檔中，我方版只有 `0050`、`智邦` 會被正確識別出來。**直接餵進 Gemini 會漏訊號或抓錯股票。**

## 手上的資源與限制

- **標準答案不限量**：官方站有 687 集逐字稿。任一集都能自己聽寫產生配對樣本，成本只有 GPU 時間（4.4 分/集）。目前已有 5 組現成配對（EP681-684 + EP687）。
- 本機有 RTX 5070 Ti (16GB)、faster-whisper 1.2.1、ctranslate2 4.8.0。
- 下游分析用 Gemini（`gemini-flash-lite-latest`），**校正這一層不希望再呼叫付費 API**，優先純本地/規則式。
- 既有程式（請假設可讀可改）：
  - `independent_transcribe.py`：`srt_to_md()` 把 .srt 轉成純文字段落 .md（無時間軸）
  - `sync_independent_transcripts.py`：`compare_paragraphs(remote_text, independent_text)` 目前用 difflib 做段落層級比對（就是上面「只回報 1 個 diff block」那支）
  - `stock_dict.py`：只 export `resolve()` / `resolve_code()`，**沒有現成的「股票名稱清單」可直接拿來用**
  - `batch.py` / `analyzer.py` / `prompt.py`：Gemini 分析管線（下游）
- `transcribe.py`（另一個專案 video-transcribe）目前**沒有** `initial_prompt` / hotwords 支援，只有 `condition_on_previous_text=False`。要加得自己改。

## 請回答這些（可自行補充你認為更重要的）

1. **對齊方法**：兩份稿的斷句、標點、段落切法都不同。要自動抽出「這個詞被聽錯成那個詞」的配對，該怎麼可靠對齊？現有的段落級 difflib 顯然不夠（88% 相似度卻只給 1 個 diff block）。字元級？詞級 + 中文斷詞？動態規劃對齊？請給具體做法與理由。

2. **雜訊過濾**：對齊後的差異裡，絕大多數是口語贅詞、標點、同義改寫。怎麼只抽出「專有名詞被聽錯」這一類，而不是全部差異？（提示：官方稿本身可能經過人工/LLM 潤稿，兩邊差異不全是聽錯。）

3. **校正表的形式與誤傷風險**：建一張「錯→對」對照表做後處理替換，最大的風險是**把本來正確的詞改錯**（例如某集真的講「奇虹」）。怎麼設計才安全？是否該限制成「只有命中股票名詞典時才替換」？還是要帶上下文條件？

4. **後處理 vs 前置提示**：走 (a) 事後校正表，還是 (b) 把股票名清單餵給 whisper 當 `initial_prompt`/hotwords，還是兩者都要？各自的效果上限與副作用（例如 initial_prompt 會不會誘發幻聽、把沒講的股票名塞進來）？請給取捨判斷。

5. **「夠準可以取代官方站」的判準**：該用什麼指標？我的想法是不該只看字元相似度，而該看**下游訊號層級的一致率**（同一集，兩份稿各自跑分析，抽出的個股與方向是否一致）。但那要花 Gemini 額度。有沒有更便宜又有代表性的代理指標？門檻該訂多少？

6. **抽樣策略**：要跑幾集配對才夠？怎麼選集數（最近 N 集？跨年份分層抽樣？）才不會過度擬合到最近的用詞。

7. **這個計畫最可能在哪裡失敗？** 特別是：官方稿本身若也是 ASR 產生的（我方尚未查證），拿它當「標準答案」的前提會不會根本站不住？如果站不住，替代驗證方式是什麼？

## 我已經排除的選項（不用再建議）

- 買網域 / 付費轉錄 API：使用者要的是本地自主。
- 只做混合模式（官方優先、我方備援）當終點：使用者明確要「最終取代」，混合只是過渡。
