## 一、CC 審查結論：方向沒問題，但有一個缺口會讓「終點」達不到

任務書 P0–P6 我逐節看過，**技術判斷與排序都成立**，兩處外審的採納也合理。
以下是我實查程式碼後找到、任務書目前沒有涵蓋的東西。

### 🔴 缺口一（阻塞終點）：整份任務書只解決「準確度」，沒有解決「交付通道」

**實查到的事實**（不是推測）：

| 事實 | 出處 |
|---|---|
| 正式分析跑在 GitHub Actions | `.github/workflows/update.yml` → `python update.py --last 5` |
| 那條路的逐字稿**來自第三方站**，每次重新下載 | `update.py:32` `from download_transcripts import main` |
| 我方聽寫稿只落在本機 `transcripts/` | `sync_independent_transcripts.py:21` |
| **`transcripts/` 在 .gitignore 第 13 行** | 691 份 .md、38MB，雲端 checkout 拿不到 |

⇒ **即使本地聽寫做到 100% 準確，正式站也拿不到它**，取代不會發生。
這正是 8/15 稍早查出的「獨立轉錄工具 8/2 就寫好也 push 了，但這條路從沒接通過」
的同一個斷點——任務書把它當成已解決，其實只解決了「產得出稿」，沒解決「稿送得到」。

**要做的**：在 P0 與 P1 之間插一個 **P0.5：交付通道決策**。四個選項（**這題影響架構，
要丹尼爾拍板，不要自己選**）：

1. **逐字稿納入版控**（拿掉 .gitignore 第 13 行）——最簡單，38MB 進 git（`.git` 目前 9.6MB）。
   代價：repo 變胖、每次新增集數都有 diff 噪音。
2. **GitHub Release / Artifact 當資產** ——repo 不胖，但 Actions 要多一步下載。
3. **物件儲存**（R2／S3）——最乾淨，但多一個外部服務與金鑰。
4. **self-hosted runner 跑在本機** ——連上傳都免了，但本機沒開機就不會跑。

我方傾向 1（先接通再優化，38MB 在可接受範圍），但**這是丹尼爾的決定，不是分身的**。

**這代表 P0.5 不是「決定」了，是「要做」了。接手的分身照這個方向做，不要再問一次。**

要注意的三件事（都是這個選項特有的，其他三個選項沒有）：

1. **本機沒開機就不會跑**——這是這個選項唯一的真代價，丹尼爾知道並接受。
   但**要讓「沒跑」看得見**：runner 離線時 GitHub Actions 的排程任務會一直排隊
   或直接失敗，**不要設計成「跑不到就安靜跳過」**。這正是本專案這週反覆踩的洞
   （產生了狀態卻沒有消費者）的同一形狀：漏跑必須留下紀錄，否則月底看報表會以為
   一切正常。分析結果的 `missed` 標記要能對回哪幾天沒跑。
2. **缺口二（P0 的 DoD）不會因為選 4 就自動解決。** 選 4 解掉的是「逐字稿怎麼送到
   正式流程」，**沒有解掉「只存在一台電腦上不叫備份」**。那 691 份仍然只在這台機器，
   Google Drive 鏡像落後 14 天。**P0 仍然必須產生一份真的離開這台機器的副本**
   ——選 4 之後這件事甚至更重要，因為執行機也是這台。兩者不可互相抵銷。
3. 🔴 **這個 repo 是「公開」的——實查結果，不是假設。**
   `gh repo view --json isPrivate` → `{"isPrivate": false}`（2026-08-15 實查）。

   GitHub 官方對這個組合有明文警告：**公開 repo 不建議用 self-hosted runner**，
   因為任何人都可以送一個 fork PR，PR 裡的 workflow 會在你的機器上執行程式碼
   （fork PR 的 `pull_request` 觸發預設需要核准，但設定一旦放寬、或有人送
   `workflow_dispatch`／改動既有 workflow 的 PR，界線就沒了）。這台機器上有
   IBKR 憑證、ai-trader 帳本、記憶正本——不是一台可以隨便讓外人執行程式碼的機器。

   **這件事已在 Discord 回報丹尼爾，等他回覆之前不要真的把 runner 掛上去。**
   三條可能的出路（他選哪條都可以做）：
   - **把 repo 轉成私有**（最乾淨；要確認沒有人在引用公開網址）
   - **維持公開但把 runner 鎖死**：關閉 fork PR 對 workflow 的觸發、
     `Settings → Actions → Fork pull request workflows` 全部要求核准，
     runner 跑在受限帳號／容器裡
   - **改選 Ａ／Ｂ／Ｃ**（納入版控／Release 資產／物件儲存）——這三個都沒有這個問題

   **不要「先設好再說」。** 設定 self-hosted runner 是難以完全回復的動作
   （機器一旦暴露過，事後撤掉不等於沒發生）。
