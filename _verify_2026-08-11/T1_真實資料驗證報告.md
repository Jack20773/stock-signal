## 4. 🔴 驗證過程中揭露的問題：本機 `episodes.json` 陳舊，導致我第一次驗到的是失真畫面

第一次產出時第二頁只有 **28 檔**、逐字稿頁只有 **680 集**。追下去發現：

| 事實 | 證據 |
|---|---|
| 本機 `episodes.json` 停在 2026-08-02，只有 680 集 | 檔案 mtime + 逐筆解析 |
| 遠端 `whatmkreallysaid.com/episodes.json` 已有 685 集 | `curl` HTTP 200，624,672 bytes，EP681–685 日期齊全 |
| DB 裡 EP681–EP685 有 23 筆訊號、`entry_date` 也正確 | 直接查 DB：EP681 07-22／EP682 07-25／EP683 07-29／EP684 08-01／EP685 08-05 |
| `attention.py:147-153` 查不到上架日就**整筆丟棄**，沒有任何警告 | 原始碼 |
| ⇒ 結果：第二頁「**目前**關注度」實際上停在 EP680（07-18），少了近一個月 | 補齊後 28 檔 → **33 檔** |

**線上有沒有這個問題？沒有。** 兩個 workflow 都在 `notifier.py` 之前先跑 `download_transcripts.py`
（`update.yml` 走 `update.py`、`publish-pages.yml` 第 39 行直接呼叫），而 `actions/cache` 只快取 `transcripts/`、
不含 `episodes.json`，所以 CI 每次都拿到新的。**這是我本機驗證環境不忠實，不是正式站的 bug。**

**但這裡有一個真實的結構性風險**：`attention.py` 丟棄訊號時是**完全靜默**的。
若哪天 CI 抓 `episodes.json` 失敗或對方站台改版，第二頁會安靜地少掉最新集數而 CI 依然綠燈——
這正是 2026-08-01 `signals_id_seq` 撞號事故的同一種型態（綠燈掩蓋真實失敗）。已列入 T2 待修。

**補齊後重跑**：`Downloaded: 5  Skipped: 680  Failed: 0` → 第二頁 33 檔、第三頁 685 集、第一頁最新至 EP685。

## 5. 第一頁另外抓到的缺陷（已修）

**站台首頁從來沒有 `<title>`，也沒有任何 `<h1>`。**

```
report_detail.html   : <title> 出現 0 次、<h1 出現 0 次
report_attention.html: <title>目前節目關注度</title>
report_transcripts.html: <title>逐字稿</title>
```

後果：瀏覽器分頁與書籤只顯示網址（`jack20773.github.io/stock-signal/`），螢幕閱讀器抓不到主標題，
搜尋引擎也拿不到頁名。第二、三頁都有，只有最重要的首頁沒有。

**修法**：`<html lang="zh-Hant">` + `<title>股癌訊號勝率追蹤</title>`，並把 header 的
`<div style="font-size:22px...">` 改成 `<h1 style="...margin:0;">`（視覺零變化，只補語意）。
